# 外部结构结论取证

> 适用范围：涉及外部站点页面结构、内嵌数据字段、接口端点的一切代码与文档。
> 目的：曾有项目将拦截页当作真实页面，据此编造页面结构，导致功能完全失效，且交付文档中
> 描述的方法与类型全部不存在。本清单用于在写下结构结论前拦截该类错误。

---

## 一、写下任何结构结论前自查

- [ ] 这条结论的证据是什么，来自保存的真实页面，还是成熟第三方提取器源码？
- [ ] 我抓到的页面确认不是拦截页吗？返回 403 且响应体含 `Generated by cloudfront` 即为拦截页。
- [ ] 保存的页面是否被工具改写过？SingleFile 会剥离 `<script>` 并把图片内联为 data URI，
      此类文件只能证明 DOM 结构，不能证明内嵌状态字段与图片地址。
- [ ] 我是否在用「公开结构知识」「通用惯例」替代取证？在本规范下这等同于无证据。
- [ ] 检索结果为零次的项，我记录下来了吗？零次同样是证据。

## 二、继承他人结论前自查

- [ ] 上一轮的结构结论标注了来源吗？未标注的一律视为未验证。
- [ ] 结论中出现的字段名、URL 形态，我能在证据里复现检索吗？
- [ ] 代码注释里「已实测」之类的表述，有对应的研究记录支撑吗？

## 三、声明修复完成前自查

- [ ] 本机能直连目标站点吗？不能，则只可声称类型检查与构建通过。
- [ ] 需要用户在浏览器登录态下验证的场景，我逐条列出来了吗？

## 四、站点专属内容的归属

具体站点的媒体对象字段表、地址构造规则与失败路径行为矩阵属该项目自身的契约，写入项目
`.trellis/spec/` 下的对应层级，并在本规范末尾以链接指向，不写入本规范正文。本规范只约束
取证方式，不记录任何单一站点的结构结论。
